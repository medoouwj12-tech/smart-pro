# SMARTGUARD PRO

منصة عربية لإدارة الأمن والقوى العاملة، مبنية على Next.js وTypeScript وPostgreSQL وPrisma. بيانات كل مؤسسة معزولة بواسطة organizationId في طبقة الخادم. تكامل الكاميرات والتحليلات غير نشط حتى إعداد خدمة وسيطة فعلية.

## المتطلبات

- Node.js 20 أو أحدث
- PostgreSQL 15 أو أحدث (Neon مناسب للنشر)

## التشغيل المحلي

1. انسخ `.env.example` إلى `.env` واضبط `DATABASE_URL` و`DATABASE_URL_UNPOOLED` و`AUTH_SECRET`. مع Neon، استخدم رابط الاتصال المجمّع (pooled، يحتوي المضيف على `-pooler`) في `DATABASE_URL`، والرابط المباشر في `DATABASE_URL_UNPOOLED`. يمكن نسخ الرابطين من لوحة Neon عبر **Connect**.
2. ثبّت الحزم: `npm install`
3. أنشئ قاعدة البيانات: `npx prisma migrate dev --name init`
4. (اختياري) أنشئ حسابًا تجريبيًا: `npm run db:seed`
5. شغّل النظام: `npm run dev`

حساب البذرة الاختياري: المؤسسة `smartguard-demo`، البريد `admin@smartguard.local`، كلمة المرور `ChangeMe123!`. غيّر كلمة المرور قبل أي استخدام منشور.

## الإنتاج

### Vercel + Neon

1. اربط Neon من Vercel Marketplace؛ التكامل يضيف `DATABASE_URL` (pooled) و`DATABASE_URL_UNPOOLED` (direct) تلقائيًا.
2. في Vercel > Project > Settings > Environment Variables أضف `AUTH_SECRET` لكل بيئة مطلوبة (Production وPreview وDevelopment). أنشئ فرع Neon منفصلًا لـPreview حتى لا تختلط بيانات المعاينة والإنتاج.
3. في Vercel > Project > Settings > Build and Development Settings اضبط **Build Command** على `npm run vercel-build`. هذا يشغّل `prisma migrate deploy` ثم يبني Next.js. بعد حفظ المتغيرات أعد النشر.
4. لا تشغّل `prisma db push` في النشر؛ ملفات `prisma/migrations` هي مصدر تغييرات المخطط. لا تستخدم قاعدة الإنتاج لمتغيرات Preview.

Vercel يحتاج صلاحية الاتصال بقاعدة Neon أثناء خطوة البناء لتطبيق الترحيلات. أثناء التطوير المحلي استخدم `npm run db:migrate` لإنشاء ترحيلات جديدة، ثم أضف ملفاتها إلى Git. استخدم HTTPS، واحتفظ بنسخ احتياطية مشفرة لقاعدة البيانات والملفات، ودوّر مفتاح الجلسات وفق سياسة التشغيل.

## الوحدات

لوحة المؤشرات، ملفات الموظفين مع سجلهم الزمني، الحضور، الإجازات، الأقسام، الورديات، الزوار، الأحداث، المخالفات، التنبيهات الحية عبر SSE، الكاميرات، قواعد الذكاء الاصطناعي، تقارير CSV، المستخدمون والأدوار المخصصة، إعداد المؤسسة، وسجل تدقيق للقراءة فقط. ربط المشرف بملف موظف يجعل بياناته محصورة بملفه وموظفيه التابعين.

## التكامل المستقبلي

سجلات الكاميرا تحتفظ ببيانات التعريف فقط وتظل `OFFLINE` افتراضيًا. لا يفتح المتصفح RTSP. أضف خدمة Camera Integration مستقلة تستقبل RTSP/ONVIF/NVR وتحوّل الأحداث الموثقة إلى API داخلي قبل تشغيل البث أو التحليلات. كل تقدير ذكاء اصطناعي يحتاج مراجعة بشرية قبل اعتماده.

## ملاحظات النطاق الأمني

الجلسات موقعة ومخزنة في Cookie من نوع HttpOnly، وكلمات المرور مجزأة باستخدام bcrypt، ومحاولات الدخول محدودة مبدئيًا لكل عنوان IP داخل كل عملية خادم. تحقق من سياسات الخصوصية والاحتفاظ بالبيانات والأدوار المخصصة قبل النشر التجاري. هذا الإصدار لا يجمع بيانات بيومترية ولا يتعرف على الوجوه. تعرّض سياسات تحديد المحاولات في الذاكرة تحتاج خدمة مشتركة مثل Redis قبل التوسع إلى عدة عمليات خادم.
